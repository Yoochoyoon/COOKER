## 개요
플랫폼, 입력 방식, AI 말풍선 구현, 익힘 연출 방식 등 실행 수단을 정리했다. [04턴페이싱.md](04턴페이싱.md)의 조리 20~30초 구간과 [02핵심메커니즘.md](02핵심메커니즘.md)의 불 조절 + 꺼내기 조작을 구현하는 기준이다.

## 결정 사항
- **엔진/플랫폼**: Unity. 모바일(터치)과 PC(마우스)를 모두 지원한다.
- **AI**: (07에서 변경) 조리 전 힌트(고향 엄마의 전화)는 사전 작성한 문구를 재료·방식·도감 상태 규칙으로 골라 보여준다. 생성형 AI는 요리 이름·최종 레시피, 완성 요리 그림을 만든다. 조리 화면의 재료 익힘 연출은 기존 2D 스프라이트를 그대로 쓰고, 완성 요리 그림만 AI 이미지 생성이다. 최종 요리와 관련된 생성(이름, 레시피, 그림)은 실시간 AI로 한다. 따라서 네트워크 연결이 필요하고, 호출 지연과 실패 처리를 구현해야 한다. 이전에 정했던 "사전 작성 문구 + 규칙 선택, LLM 실시간 생성 안 씀"은 폐기했다. 힌트는 정답을 말하지 않도록 사전 작성 단계에서 검수한다. (사전 작성 결정은 힌트에만 유지되고, 요리 이름·레시피·그림에는 적용되지 않는다)
- **익힘 연출**: 2D 스프라이트. 재료마다 날것·적게 익힘·알맞음·많이 익힘·탄 것 5장을 준비하고, 익힘 값이 단계 경계를 넘을 때 그림을 한 장씩 바꾼다. (처음엔 3장 보간이었으나 5단계로 확정)

## 상세 규칙/수치
- 입력 공통화: 터치와 마우스를 같은 입력 추상화로 처리한다. 불 조절은 드래그/슬라이드, 꺼내기는 탭/클릭으로 매핑한다는 방향만 있다. 화력 단계 수는 02의 미해결 항목이다.
- 데이터 구조(초안, 정하지 않음): 재료(가격, 유통기한, 적합 방식, 스프라이트 5장), 방식(익는 속도, 적정 구간 폭), 도감(재료별 기록과 힌트 단계), 말풍선 문구 풀(조건 태그별).
- 아직 정하지 않은 항목:
  - UI 해상도와 모바일/PC 레이아웃 차이
  - 도감 저장 방식(로컬 저장 여부)
  - 말풍선 규칙 선택의 조건 목록
  - 사운드와 식사 연출 범위

## 밸런스 고려사항 / 트레이드오프
- 터치와 마우스를 모두 지원하면 손가락이 화면을 가려 익힘 단서가 보이지 않을 수 있다. 조리 화면에서 조작 영역과 재료 영역을 분리해 배치해야 한다.
- 스프라이트 5단계는 3장 보간보다 제작량이 늘지만, 재료 수만큼 아트가 늘어난다. 초기 재료 수를 작게 잡는 편이 안전하다.
- 생성형 AI를 쓰면 호출 비용과 지연, 오프라인 동작 여부, 정답 노출 위험, 같은 조합의 이름 일관성을 관리해야 한다.
- 버린 대안: 사전 작성 문구 + 규칙 선택(요리 이름·레시피가 조합마다 달라 한계), 셰이더 색 변화와 3D 텍스처(제작 비용).
