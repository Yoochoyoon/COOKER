# 27 전체 익힘 명세

재료마다 따로 있던 익힘을 없애고, 팬 하나의 익힘 값 하나로 판정하는 변경의 구현 명세다. 담당은 [윤혁진](#9-담당), 판정 파일 승인과 수치는 유초윤 님이 맡는다.

> **미확정** 표시 항목은 팀에서 확정한 뒤 이 문서를 고친다.

## 1. 목적

- 조리 중 재료별 익힘을 없애고, 팬 전체의 익힘 값 하나로 판정한다.
- 꺼내기는 조리 완료 시점에 한 번만 한다.
- 재료 넣는 순서 판정(`docs/28` 예정)은 그대로 두고, 순서가 틀리면 그 보정을 전체 익힘에 반영한다.

## 2. 익힘 값 계산

| 항목 | 내용 |
| --- | --- |
| 전체 익힘 값 | 조리 중 누적되는 값 하나. 0~100 범위를 쓴다. |
| 재료별 값 | 계산 중에만 쓴다. 화면에는 보이지 않는다. |
| 계산 방식 | **미확정.** 제안은 재료 익힘의 평균이다. 대안은 가장 덜 익은 재료나 가장 빨리 익는 재료에 맞추는 방식이다. |
| 순서 보정 | 순서가 틀리면 전체 값에 보정 계수를 곱한다. 계수는 `BalanceData`에 둔다. |

## 3. 판정 단계

조리 완료 시점의 전체 익힘 값으로 다섯 단계 중 하나를 정한다. 기준 값은 `BalanceData`에 둔다.

| 단계 | 조건 | 꺼냈을 때 |
| --- | --- | --- |
| 날것 | 값이 40 미만 | 실패(굶음) |
| 적게 익힘 | 40 이상, 적정 구간 시작 전 | 성공, 만족도 감소 |
| 알맞음 | 적정 구간 | 성공, 만족도 최대 |
| 많이 익힘 | 구간 끝 이후, 99 이하 | 성공, 만족도 감소 |
| 탄 것 | 100 이상 | 실패(굶음) |

적정 구간은 방식마다 다르다. 값은 `docs/09`를 따른다. 굽기 60~75, 볶기 55~80, 끓이기 50~90이다.

## 4. 꺼내기

- 꺼내기는 조리 완료 버튼을 누를 때 한 번만 한다.
- 재료별로 따로 꺼내던 기존 흐름은 제거한다.
- 판정 결과 단계는 화면과 결과 계산에 함께 넘긴다.

## 5. 코드 연결 (제안)

새 파일 `Cook.Whole.cs`에 partial class로 둔다. 기존 파일에는 호출만 추가한다.

- **속성:** 전체 익힘 값(0~100), 현재 단계(다섯 단계 중 하나), 재료별 계산값(내부용).
- **메서드:** 재료 익힘을 전체 값에 반영, 순서 보정 적용, 조리 완료 시 단계 판정.

`Cook.cs`는 유초윤 님 담당이므로, 수정 전에 승인을 받는다.

## 6. 화면 연결 지점

- 화면에는 전체 익힘 값과 단계만 넘긴다.
- 화면 표시(게이지, 단계 텍스트, 색 변화)는 **유초윤 님이 맡는다.** 이 명세에서는 다루지 않는다.

## 7. 호환 (주의)

다음 항목이 재료별 익힘을 기준으로 되어 있다. 바꾸면 기존 저장과 맞지 않는다.

| 대상 | 현재 기준 | 처리 |
| --- | --- | --- |
| 요리 사진 키 (`DishPhoto.Key`) | 재료별 익힘과 방식 | **결정.** 완성 요리 사진은 익힘을 빼고, 재료 조합과 방식으로만 고른다. 익힘은 맛과 만족도에만 쓴다. 사진 파일은 "잘 완성된 요리" 한 장으로 통일한다. |
| 도감 파일 (`dex.json`) | 요리 키(사진 키와 같은 기준) | **미확정.** 키에서 익힘을 빼면 같은 재료 조합의 기록이 하나로 합쳐진다. 도감 종류 수와 칭호 기준이 바뀌므로 유초윤 님이 확인한다. |
| 기록 파일 (`run.json`) | 진행 상태 | 기존 필드를 바꾸지 않는다. |

규칙: 저장과 식별에 쓰는 이름은 바꾸지 않는다. 꼭 바꿔야 하면 변환 코드를 같이 넣는다(`CLAUDE.md`).

## 8. 수치 목록 (`BalanceData`)

- 단계 경계 값 (40, 99, 100)
- 방식별 적정 구간 (제안값은 `docs/09`)
- 순서 보정 계수
- 구간 밖 보정 값 (불 바늘 명세 `docs/26`과 연결)

수치를 정하면 바꾼 값과 이유를 `docs/09`에 한 줄씩 남긴다.

## 9. 담당

- **윤혁진:** `Cook.Whole.cs`(새 파일), 전체 익힘 계산, 단계 판정, 꺼내기 흐름, 순서 보정 연결.
- **유초윤:** `Cook.cs` 호출 승인, `BalanceData` 수치, 요리 사진 키 결정, `dex.json` 변환 확인, `docs/09` 기록, 화면 표시.

## 10. 단계별 작업 (동결 일정 고려)

1. **이번 주(11/26~27):** 전체 값 계산만 추가한다. 기존 재료별 판정은 그대로 둔다. 전체 값은 화면 확인용으로만 노출한다.
2. **다음 주:** 꺼내기를 전체 판정으로 바꾼다. 요리 사진 키와 도감 변환을 함께 처리한다.

## 11. 테스트

- 재료 익힘을 바꾸면 전체 값이 그에 맞춰 바뀌는지 확인한다.
- 다섯 단계 경계(40, 99, 100)에서 단계가 맞게 바뀌는지 확인한다.
- 순서를 틀렸을 때 전체 값이 보정되는지 확인한다.
- 네 방식 모두에서 적정 구간이 맞는지 확인한다.
- 기존 저장 파일(`run.json`, `dex.json`)을 읽어도 오류가 없는지 확인한다.
- 빌드 전에 인터넷을 끊고 한 판을 끝까지 돌린다.

## 12. 확정이 필요한 것

1. **전체 값 계산 방식:** 평균으로 할지, 가장 덜 익은 재료나 가장 빨리 익는 재료에 맞출지.
2. **요리 사진 키:** 전체 단계와 재료 조합으로 바꿀지, 기존 키를 살릴지.
3. **일정:** 이번 주에는 계산만 넣고, 판정 교체는 다음 주로 미루는 방식이 맞는지.
