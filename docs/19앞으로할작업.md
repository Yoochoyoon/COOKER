# 19. 앞으로 할 작업 (기말 제출 기준, 2주)

공모전이 아니라 **학교 기말 프로젝트 제출**이 목표다. 기준은 "시연이 안정적이고, 설계 근거와 테스트 결과가 문서로 남아 있는가"다.

## 원칙

- **화면은 코드로 그린다.** 프리팹 전환은 하지 않는다 (협업 충돌과 작업량 때문).
- **AI 기능은 실행 중에 쓰지 않는다.** 요리 그림은 미리 만들어 넣은 파일만 쓴다. 시연 때 인터넷과 크레딧에 기대지 않는다.
- **수치는 `Data.cs`에서만 고친다.** 바꾸면 이유를 `docs/09`에 한 줄 남긴다.
- **매일 커밋한다.** Unity가 자동으로 바꾼 설정 파일(`EditorPipelineConfig.json` 등)은 올리지 않는다.
- **범위를 넘지 않는다.** 칭호 확장, 영구 버프, 모바일은 이번 범위가 아니다.

### 협업 규칙

1. **작업 전 pull, 끝나면 push.** 시간 고정 없이, 각자 작업을 마치면 `main`에 올립니다. 합치기는 유초윤이 맡습니다.
2. **공유 파일은 요청으로만 바꾼다.** 예: "Data.cs에서 달걀 가격 500 → 450 부탁". 주인이 바꿉니다.
3. **같은 날 같은 파일을 건드리면 먼저 말한다.**
4. **커밋 메시지에 파트 이름을 붙인다.** 예: `[조리] 뒤집기 연출 추가`, `[도감] 필터 정렬 수정`.
5. **자동 생성 파일은 커밋하지 않는다.** `EditorPipelineConfig.json`, `UniversalRP.asset` 등은 빼고 올립니다.
6. **씬은 유초윤만 고친다.** 나머지는 코드와 에셋으로 작업합니다.
