# AI 요리 그림 생성: 비교 시험 계획

AI 기능이 이 게임의 핵심이므로 일정에서 가장 먼저 한다. 요리가 끝나면 **요리 이름·한 줄 설명(Claude)**과 **요리 그림(이미지 모델)**을 만들어 식사 화면과 도감에 보여 준다. 게임의 숫자(만족도, 가격, 난이도)에는 AI를 쓰지 않는다. 결과가 매번 달라져 밸런스를 잡을 수 없기 때문이다.

> 2026-11-04 갱신: 시험은 끝났고 결과와 현재 구현은 아래 7~9장에 있다. 1~6장은 처음 계획(참고용)이다.

## 1. 일정 변경
| 구분 | 전 | 후 |
|---|---|---|
| AI | 마지막에 시간이 되면 | **지금 시작. 1순위** |
| 일정이 밀릴 때 버리는 순서 | AI 연동이 첫째 | 효과음 → 힌트 확장 → 스프라이트 순. AI는 마지막에 버린다 |

진행 순서는 아래와 같다.

1. **비교 시험 (2~3시간)**: 이미지 모델 2~3개를 같은 조건으로 비교한다.
2. **모델 결정**: 5장의 점수표로 정한다.
3. **Unity 연결 (반나절)**: 요청, 대기 화면, 저장, 대체 처리까지.
4. **미리 만든 그림 채우기**: 발표장 인터넷이 불안할 때를 위한 대비책.
5. **리허설**: 발표장과 같은 조건(인터넷, PC)으로 한 판.

## 2. 담당
- 비교 시험, 모델 결정: **B 파트**
- 시험 결과 판단(그림체가 게임과 맞는지): **C 파트(오너)**
- Unity 연결: B 파트 (`GameFlow.cs`, 새 `AiNamer.cs`, 새 `AiDishImage.cs`)

## 3. 후보 고르는 기준
이름은 시험 전에 정하지 않는다. 아래 조건을 만족하는 서비스 2~3개를 B 파트가 고른다.
- API로 호출할 수 있다(웹 화면만 있는 서비스는 제외).
- 한 장 생성에 20초 이하.
- 장당 비용이 공개돼 있고, 한도를 걸 수 있다.
- 가능하면 **참조 이미지(오너님의 재료 그림)를 넣을 수 있다**. 그림체를 맞추기 쉽다.
- 가능하면 투명 배경이나 단색 배경을 지원한다.

## 4. 시험 문제 6개 (모든 후보에 똑같이)
게임에서 실제로 나올 조합이다. 익힘 상태를 그림에 반영하는지 보려고 상태를 섞었다.

| # | 요리 | 방식 | 상태 |
|---|---|---|---|
| 1 | 달걀 | 굽기 | 알맞음 |
| 2 | 달걀 + 김치 | 볶기 | 알맞음 |
| 3 | 돼지고기 + 양파 | 볶기 | 많이 익힘 |
| 4 | 두부 + 감자 | 끓이기 | 알맞음 |
| 5 | 감자 | 굽기 | 탄 것 |
| 6 | 돼지고기 + 김치 | 끓이기 | 적게 익힘 |

### 프롬프트 틀
```
{고정 스타일}
Dish: {방식}ed {재료들}, {상태 설명}, one plate, centered, no text, no hands.

고정 스타일:
Hand-drawn 2D cartoon food illustration, thick outlines, warm flat colors,
Korean home cooking, simple white or transparent background, no text or letters.
```
상태 설명은 알맞음 = "perfectly cooked", 많이 익힘 = "overcooked, dark edges", 탄 것 = "burnt black", 적게 익힘 = "undercooked, pale".

- 모든 후보에 **글자 하나도 바꾸지 않고** 같은 프롬프트를 쓴다.
- 문제마다 **3번씩** 생성해서 안정적인지 본다(총 18장 × 후보 수).
- 참조 이미지를 지원하는 후보는 참조 있음/없음을 한 번씩 더 시험한다.

## 5. 점수표 (후보마다 채운다)
항목마다 1~5점. 5가 가장 좋다.

| 항목 | 보는 것 |
|---|---|
| 재료 인식 | 달걀, 김치 같은 재료가 보이는가 |
| 상태 반영 | 탄 것과 알맞은 것이 구분되는가 |
| 그림체 | 게임 그림체와 맞는가 (C 파트가 점수) |
| 일관성 | 같은 문제 3장이 비슷한 품질인가 |
| 배경 | 접시 그림만 깔끔하게 쓸 수 있는가 |
| 글자 섞임 | 이상한 글자나 손이 안 나오는가 |

숫자로 기록하는 항목은 아래와 같다.
- 평균 생성 시간(초)
- 장당 비용
- 실패율(오류, 거부)

## 6. 결정 규칙
- 평균 생성 시간 **20초 이하**, 실패율 **10% 이하**를 먼저 넘겨야 한다.
- 그 안에서 점수 합계가 가장 높은 후보를 쓴다.
- 비슷하면 **더 싸고 한도를 걸 수 있는** 쪽을 쓴다.
- 조건을 넘는 후보가 없으면: 요리 그림 생성은 포기하고 **미리 만든 그림 + Claude 이름·설명**으로 간다. 이 경우에도 AI는 들어간다.

## 7. 현재 구현 (2026-11-04)
| 파일 | 하는 일 |
|---|---|
| `DishNamer.cs` | 요리 이름을 AI로 짓는다. 먼저 `Recipes.NameOf`의 규칙 이름을 보여 주고, 도착하면 바꾼다. 같은 요리는 같은 이름을 저장해 쓴다. |
| `DishPhoto.cs` | 요리 그림 생성. 작업 대기열, 디스크 캐시(`persistentDataPath/DishPhotos/<키>.png`), 서비스 순서 처리. |
| `GameFlow.cs` | 식사 화면·도감에서 그림을 요청하고, 도착하면 교체한다. |

### 그림 규칙
- **성공한 요리만 만든다.** 망친 요리(날것·탄 것)는 AI를 부르지 않고 흰 접시 임시 그림(`DishPhoto.Placeholder`)을 쓴다. 도감에는 성공한 요리만 들어가기 때문이다.
- 프롬프트는 "귀여운 2D 카툰, 굵은 갈색 외곽선, 파스텔, 흰 접시" 고정 스타일(`Cute`)에 재료·방식·익힘 상태 문구를 붙인다. 탄 것은 "전부 검은 숯"으로 강하게 적어 두었다.
- 같은 조합과 스타일은 캐시 키가 같아 다시 요청하지 않는다. 스타일 이름(`Style`)을 바꾸면 모두 새로 만든다.

### 서비스 순서 (앞에서부터 시도, 실패하면 다음)
| 순서 | 서비스 | 필요한 설정 | 비고 |
|---|---|---|---|
| 1 | **BAZE** `gpt-image-2.5-sunburst` | `BAZE_API_KEY` (모델은 `BAZE_IMAGE_MODEL`로 바꿀 수 있다) | 유료. 그림체가 가장 좋았다 |
| 2 | OpenAI 이미지 | `OPENAI_API_KEY` | 유료 |
| 3 | Hugging Face FLUX.1-schnell | `HF_TOKEN` | |
| 4 | Pollinations (키 있음) | | |
| 마지막 | Pollinations 무료 | 없음 | 스타일 문구를 잘 따르지 않는다. 키가 없을 때의 최종 대비책 |

- **에디터에서 테스트하는 동안은 무료 서비스만 쓴다**(`PaidAllowed`). 빌드는 항상 유료를 쓴다. 에디터에서 유료를 시험하려면 `COOKER_PAID_IN_EDITOR=1`을 설정한다.
- 무료와 유료 그림은 캐시 키가 달라(`-free`) 서로 덮어쓰지 않는다.
- 키는 환경변수 또는 **`UserSettings/CookerApiKeys.txt`**(`이름=값` 한 줄씩, 깃에 올라가지 않는다)에서 읽는다.

## 8. 지켜야 할 것
- **API 키는 코드나 레포에 넣지 않는다.** 위 파일에만 둔다. 채팅 등에 노출됐으면 폐기하고 새로 만든다.
- 빌드 파일에 키가 들어가면 꺼낼 수 있다. 발표용 PC에만 두고 사용 한도가 낮은 키를 쓴다.
- 크레딧 소모는 장당 대략 sunburst 11~14, fast-sdxl 5. 시험과 리허설 분량도 계산에 넣는다.
- AI 그림은 요리 완성 그림에만 쓴다. 재료, 배경, 버튼은 오너가 직접 그린 것임을 문서와 발표에서 구분한다.
- 경진대회 규정에 AI 생성물 사용 조건이 있는지 확인한다.
- 발표장에 인터넷이 없으면 그림은 임시 접시로 나온다. 리허설 때 미리 만들어 캐시를 채워 두는 방법이 있다.

## 9. 시험 기록
같은 프롬프트(달걀 등 대표 요리)로 BAZE 모델 몇 개를 한 번씩 비교했다. 점수표 대신 눈으로 비교한 결과다.

| 후보 | 장당 크레딧 | 결과 |
|---|---|---|
| 무료 Pollinations | 0 | 스타일을 무시하고 사실적인 사진이 나온다 |
| BAZE `fast-sdxl` | 5 | 가장 싸지만 그림체가 게임과 덜 맞는다 |
| BAZE `ideogram/v4/fast` | 10.5 | 무난 |
| BAZE `z-image-turbo` | 15 | 무난하지만 비싸다 |
| BAZE `gpt-image-2.5-sunburst` | 약 11~14 | **채택.** 게임 그림체와 가장 가깝다 |
| Gemini 이미지 | - | 무료 한도가 0이라 못 썼다 |
| OpenAI 이미지 API | - | 무료가 아니라 기본 서비스로 쓰지 않았다 |

결정: 성공한 요리에만 **sunburst**를 쓰고, 에디터 테스트는 무료로 한다.
미확인: 실제 빌드에서 유료 경로가 도는지(API 호출과 코드만 확인함).
