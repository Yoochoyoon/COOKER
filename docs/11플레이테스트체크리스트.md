## 개요
3일차 오후에 지인 2~3명에게 설명 없이 한 판을 해 보게 할 때 쓰는 관찰 시트다. [06](06플레이테스트와리스크.md)의 검증 질문을 실제 테스트 순서로 풀었다.

## 진행 방법
1. 규칙 설명 없이 플레이어에게 노트북을 건네고, 질문에 답하지 않는다. 막히는 지점을 기록만 한다.
2. 한 판은 10~15분이다. 실패해도 한 번은 다시 하게 한다.
3. 끝나면 아래 설문 질문 5개를 묻는다.
4. 테스터 이름 대신 번호(P1, P2...)로 기록한다.

## 관찰 항목 (플레이 중 체크)
| 구간 | 확인할 것 | P1 | P2 | P3 |
|---|---|---|---|---|
| 타이틀~장보기 | 시작 버튼을 바로 찾는가 | | | |
| 장보기 | 최소 6개 규칙을 이해하는가, 예산 안에서 고르는가 | | | |
| 장보기 | 적합 방식이 안 보여서 막히는가 | | | |
| 첫날 가이드 | 화력 버튼과 [꺼내기]를 설명 없이 찾는가 | | | |
| 조리 | 색 변화만 보고 꺼내는 시점을 판단하는가 | | | |
| 조리 | 방식별 고유 조작(뒤집기·젓기·뚜껑)을 알아차리는가 | | | |
| 조리 | 몇 번째 시도에 성공했는가 (실패 횟수) | | | |
| 하루 선택 | 유통기한 임박 재료를 먼저 쓰려고 하는가 | | | |
| 하루 선택 | 엄마 힌트를 읽는가, 도움이 되는가 | | | |
| 식사 | 반응 문구와 만족도 숫자를 보는가 | | | |
| 전체 | 몇 일차에서 실패했는가, 완주했는가 | | | |

## 막힘 기록
막힌 순간마다 한 줄로 적는다. 형식: `[일차/화면] 무엇을 하려다 → 어떻게 막혔다`

## 설문 질문 (플레이 후)
1. 조리하는 20~30초가 재미있었나요? (1~5)
2. 규칙이 복잡하다고 느꼈나요? 어느 부분이 가장 부담스러웠나요?
3. 굶으면 끝난다는 규칙이 긴장감이 있었나요, 아니면 짜증이 났나요?
4. 한 번 더 하고 싶은가요? 왜 그런가요?
5. 가장 기억에 남는 순간은 무엇인가요?

## 판정 기준 (임시)
| 질문 | 합격선 |
|---|---|
| 조리 재미 | 평균 3.5점 이상 |
| 재플레이 의사 | 3명 중 2명 이상 "다시 하고 싶다" |
| 설명 없이 이해 | 3명 중 2명 이상이 첫날 가이드를 넘긴다 |
| 복잡도 | "복잡하다"는 응답이 3명 중 1명 이하 |

합격선은 정해진 값이 아니라 처음 쓰는 기준이다. 테스트 후 팀이 조정한다.

## 결과에 따른 조정 (우선순위)
- 조리 구간이 너무 빡빡하다는 의견이 많으면: `Data.cs`의 방식별 `lo`, `hi`를 넓힌다. (굽기부터)
- 규칙이 복잡하다는 의견이 많으면: 줄일 후보는 도감, 다양성 점수, 유통기한 순서로 검토한다.
- 첫 주 학습이 가혹하다는 의견이 많으면: 장보기 화면에 재료 적합 방식을 일부 공개하는 방안을 검토한다.
- 굶음 실패가 너무 일찍 나오면: 첫날 가이드 외에 둘째 날도 실패를 봐주는 방안을 검토한다.
