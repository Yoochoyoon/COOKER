## 개요
그림 파일을 정해진 이름으로 넣기만 하면 게임에 나온다. 코드를 고칠 필요 없다. 파일이 없으면 지금처럼 단색으로 대신 그려지므로, 한 재료씩 넣어도 게임은 깨지지 않는다.

## 익힘 5단계
색이 서서히 변하지 않고, 단계가 바뀔 때 그림이 한 장씩 통째로 바뀐다. 단계 기준은 꺼내기 판정과 같다.

| 단계 | 파일 접미사 | 익힘 값 | 꺼내면 |
|---|---|---|---|
| 날것 | `raw` | 40 미만 | 실패(굶음) |
| 적게 익힘 | `under` | 40 ~ 적정 구간 시작 전 | 성공, 만족도 감소 |
| 알맞음 | `good` | 적정 구간 | 성공, 만족도 최대 |
| 많이 익힘 | `over` | 구간 끝 ~ 99 | 성공, 만족도 감소 |
| 탄 것 | `burnt` | 100 이상 | 실패(굶음) |

- 적정 구간은 방식마다 다르다. 굽기 60~75, 볶기 55~80, 끓이기 50~90 ([09](09재료와방식수치초안.md) 참고). 굽기는 구간이 좁아 `good` 그림이 짧게 보인다.
- 그림 단서가 유일한 판단 근거이므로, 다섯 그림의 차이가 분명해야 플레이어가 꺼낼 때를 알 수 있다. 특히 `under`/`good`/`over`가 구분되어야 한다.

## 넣는 곳과 파일 이름
`Assets/Resources/Art/` 폴더에 넣는다. (Resources 폴더 이름과 위치를 바꾸면 안 된다.) 재료당 5장, 6종이면 총 30장이다.

| 재료 | id | 파일 5장 |
|---|---|---|
| 달걀 | `egg` | `egg_raw`, `egg_under`, `egg_good`, `egg_over`, `egg_burnt` (.png) |
| 두부 | `tofu` | `tofu_raw`, `tofu_under`, `tofu_good`, `tofu_over`, `tofu_burnt` |
| 양파 | `onion` | `onion_raw`, `onion_under`, `onion_good`, `onion_over`, `onion_burnt` |
| 감자 | `potato` | `potato_raw`, `potato_under`, `potato_good`, `potato_over`, `potato_burnt` |
| 돼지고기 | `pork` | `pork_raw`, `pork_under`, `pork_good`, `pork_over`, `pork_burnt` |
| 김치 | `kimchi` | `kimchi_raw`, `kimchi_under`, `kimchi_good`, `kimchi_over`, `kimchi_burnt` |

- **한 재료의 5장이 모두 있어야** 그림으로 나온다. 일부만 있으면 그 재료는 단색으로 나온다.

## 조리 화면 구성
재료는 조리 화면에서 도마(넣기 전, 오른쪽 위), 팬·웍·냄비(익는 중, 왼쪽), 접시(꺼낸 뒤, 오른쪽 아래)로 옮겨 다닌다. 도마(대기열)에서는 장보기와 같은 **`<id>_shop.png`**가 보이고, 팬에 넣으면 **익힘 5단계 그림**(`<id>_raw`~`_burnt`)으로 바뀐다. 5단계 그림은 팬 안에서 작게 보이므로 형태가 알아보이게 그린다. 재료 위에는 익힘 게이지가 뜬다.

## 그림 규격
- 형식: PNG, 배경 투명.
- 크기: 정사각형 **512 x 512** 권장. 5장은 같은 크기와 같은 위치에 그려야 단계가 바뀔 때 흔들리지 않는다.
- 가운데에 재료를 크게 그린다. 화면에서는 팬 안에 큰 사각형 칸으로 보이고 가로세로 비율은 유지된다.
- 형태는 비슷하게 두고 색과 질감을 단계별로 바꾼다. (날것 → 덜 익음 → 알맞음 → 과함 → 탄 것)

## 단색일 때(그림이 없을 때)
같은 5단계를 `Data.cs`의 재료 색(`raw`, `cooked`, `burnt`)으로 나눠 보여 준다. 날것 = raw, 적게 익힘 = raw와 cooked의 중간, 알맞음 = cooked, 많이 익힘 = cooked와 burnt의 중간, 탄 것 = burnt.

## 넣은 뒤 확인하는 방법
1. 파일을 `Assets/Resources/Art/`에 넣는다. Unity가 가져오게 잠시 기다린다.
2. 각 그림을 클릭해 Inspector에서 **Texture Type이 `Sprite (2D and UI)`** 인지 확인한다. (2D 프로젝트는 기본값이다. 아니면 바꾸고 Apply.)
3. Play를 눌러 해당 재료로 조리해 본다. 약불로 하면 단계가 천천히 바뀌어 보기 쉽다.
4. 안 나오면: 파일 이름 철자, 폴더 위치, 5장이 모두 있는지, Texture Type을 순서대로 확인한다.

## 배경·장보기·조리 화면 그림 (연결됨)
모두 `Assets/Resources/Art/`에 둔다. **글자와 숫자는 그림에 넣지 않는다**(코드가 위에 얹는다). 그림이 없으면 단색으로 대신 그려서 게임은 깨지지 않는다.

| 파일 | 쓰이는 곳 | 규격 |
|---|---|---|
| `bg_title.png`, `title_logo.png`, `title_start.png`, `title_exit.png` | 타이틀 (배경 + 로고 + START·EXIT) | 배경 16:9. 나머지는 투명 PNG이고 위치는 원본 타이틀 이미지(1671x941)를 따른다. 로고·START·EXIT 3장이 모두 있어야 나온다 |
| `bg_shop.png` | 장보기 배경 | 16:9. 재료 표와 장바구니는 그림에 넣지 않는다 |
| `shop_basket_back.png`, `shop_basket_front.png` | 장바구니 뒤·앞 | 투명 PNG, 약 680x620. **재료가 이 둘 사이에 끼여** 보인다. 앞 그림은 입구(재료가 보일 자리)가 투명이어야 한다. 한 장짜리 `shop_basket.png`만 있어도 된다 |
| `<id>_shop.png` | 장보기 줄·장바구니·조리 대기열·하루 선택 재료 아이콘 | 정사각형 투명 PNG, 재료 6장 |
| `bg_cook_grill.png`, `bg_cook_wok.png`, `bg_cook_pot.png` | 조리 화면 배경 (굽기 팬 / 볶기 웍 / 끓이기 냄비) | 16:9, 1920x1080. 왼쪽에 버너와 조리도구, 오른쪽 위 도마, 오른쪽 아래 접시. **세 장의 도마·접시·버너 위치가 같아야** 한다(코드가 같은 좌표를 쓴다) |
| `cook_burner_bar.png` | 조리 화면 왼쪽 아래 바 (밸브와 조작 칸이 올라간다) | 가로로 긴 투명 PNG, 약 1079x195 |
| `cook_timer.png` | 조리 화면 왼쪽 위 타이머 알약 | 투명 PNG, 약 320x116. 글자는 코드가 쓴다 |
| `cook_tip.png` | 조리 화면 오른쪽 아래 엄마 말풍선 | 투명 PNG, 약 694x216 (**한 장짜리**로 가져온다. Unity가 여러 조각으로 자동 분할하면 칸 전체로 늘어나 커진다) |
| `cook_flip_btn.png` | 굽기의 뒤집기 버튼 배경 | 투명 PNG, 약 446x160 |
| `cook_fire_on.png`, `cook_fire_off.png` | 불 세기 아이콘 | 지금 조리 화면은 밸브 손잡이를 써서 쓰지 않는다 |

- 팬·웍·냄비의 위치는 코드의 `StartCook`/`PlaceItem`에 화면 비율로 적혀 있다. 배경 그림의 배치를 바꾸면 그 좌표도 같이 고친다.
- 조리 도구 그림은 `Resources/Art/Kitchen/`에 선택으로 넣을 수 있다(`tablecloth`, `cutting_board`, `knob` 등). 하루 선택 화면의 식탁보·도마와 조리 화면의 밸브 손잡이는 없으면 코드가 그린다.
- 요리 **완성 그림은 AI가 만든다**(성공한 요리만). 자세한 것은 [docs/15](15AI요리그림비교시험계획.md).

## 지금은 지원하지 않는 것
다음은 아직 그림이 연결되지 않았다.
- 식사·결산 화면 배경
- 볶기·끓이기의 조작 칸(젓기 칸·뚜껑 칸) 그림 (지금은 단색 카드)
- 엄마 전화 캐릭터

## 일정이 빠듯할 때
재료 6종을 한 번에 다 그리지 않아도 된다. 자주 쓰는 달걀, 돼지고기부터 5장씩 넣고 나머지는 단색으로 둔 채로 진행해도 된다.
