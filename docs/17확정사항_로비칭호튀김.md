# 확정사항: 로비 · 칭호 · 튀김 해금 (2026-11-04)

멘토링 피드백(시스템은 좋다, **도감 활용**과 **마지막**이 아쉽다)을 반영해 아래 세 가지를 추가한다.
`확정`은 팀 결정, `초안`은 담당자가 만들면서 조정해도 되는 값이다.

## 담당
| 담당 | 일 |
|---|---|
| 영은 | 로비 화면 (구성만, 디자인은 나중) |
| 윤혁진 | 칭호 시스템, 튀김 재료·튀김 조리 추가와 해금 |
| 유초윤 | 최종 UI 디자인 |

작업 규칙: 새 기능은 새 파일로 만들고 `GameFlow.cs`에는 호출 한 줄만 넣는다. 시작 전에 `git pull`.

## 1. 로비 화면 (확정)

### 화면 흐름
```
타이틀 → 로비 → 장보기 → [ 7일 → 일주일 정산 ] → 로비(진입 시 해금 연출) → 로비 → 장보기 → ...
```
- 로비는 한 주가 끝날 때마다 돌아오는 거점이다. 정산이 끝나면 로비로 복귀하고, **로비에 들어올 때 새로 얻은 칭호와 해금(튀김 등) 연출**을 먼저 보여 준 뒤 일반 로비 상태가 된다.
- 로비의 **게임 시작** 버튼을 누르면 장보기로 간다.

### 로비에 있는 것
| 요소 | 내용 | 담당·시점 |
|---|---|---|
| 현재 일차 | 몇 일 차인지 표시 | 영은 (이번 작업) |
| 보유 금액 | 현재 가진 돈 표시 | 영은 (이번 작업) |
| 도감 버튼 | 도감 화면을 연다 | 영은 (이번 작업) |
| 게임 시작 버튼 | 장보기로 이동 | 영은 (이번 작업) |
| 주인공 캐릭터 | 머리 위에 **현재 칭호**를 표시한다. 캐릭터를 누르면 칭호 목록이 열린다 | 유초윤 (후순위) |
| 칭호 목록 | 전체 칭호, 잠긴 칭호의 **해금 조건과 힌트**, **대표 칭호 변경** | 윤혁진(칭호 시스템) + 유초윤 (캐릭터 연결 후) |
| 냉장고 버튼 | 이미지 버튼. 누르면 **현재 가진 재료** 목록을 보여 준다 | 유초윤 (후순위) |

- 주인공 캐릭터와 냉장고는 아직 확정되지 않은 기능이라 **후순위**다. 영은님은 이 둘이 들어갈 자리를 비워 두고 나머지 요소로 화면 구성만 만든다. 디자인은 나중에 입힌다.
- 칭호 목록을 캐릭터 없이도 임시로 열 수 있게(예: 임시 버튼) 해 두면 칭호 시스템 테스트에 편하다.
- 로비에서도 도감과 칭호를 볼 수 있으려면 도감 화면이 "게임 중이 아닐 때"도 열려야 한다. (저장 데이터를 읽어서 보여 준다)
- "현재 일차", "보유 금액"은 한 판이 진행 중일 때의 값이다. 새 게임 시작 직전의 로비는 1일 차와 시작 예산을 보여 준다.

### 정해야 할 것 (영은·혁진 상의)
- 로비의 일차·금액 표시는 `Run` 데이터를 읽어서 쓴다. 한 주가 끝나면 `Run`이 넘어가는 시점(주차 진행)과 로비 복귀 시점을 맞춰야 한다.
- 대표 칭호를 바꾸면 저장 파일에 대표 칭호도 같이 저장한다.

## 2. 칭호 (확정)
- **판정 시점**: 한 주가 끝나는 결산 때. 새 칭호가 있으면 결산 화면에서 알려 준다.
- **기준**: 누적 도감 수집 수 + 방식별 수집 수.
- **저장**: 도감, 칭호, 해금 상태는 **파일로 저장**해서 다음 판에도 이어진다. (`persistentDataPath`의 JSON 한 파일을 권장)

| 칭호 | 조건 | 보상 |
|---|---|---|
| 집밥 입문 | 도감 5종 | 없음 |
| 자취 생존자 | 도감 10종 | **튀김 해금** (재료 + 조리) |
| 동네 밥집 사장 | 도감 20종 | 없음 (초안) |
| 한식 달인 | 도감 35종 | 없음 (초안) |
| 굽기 장인 / 볶기 장인 / 끓이기 장인 | 해당 방식 5종 | 없음 |
| 튀김 명인 | 튀김 3종 | 없음 |

- 수치는 **초안**이다. 한 판에서 서로 다른 요리가 대략 7개 안팎이라, 10종은 1~2주 안에 닿게 잡았다. 직접 플레이하며 조정한다.
- 영구 버프 같은 다른 보상은 프로토타입 이후로 미룬다.

## 3. 튀김 해금 (확정: 재료와 조리를 한 번에 같이)
**자취 생존자**를 얻으면 **새우**와 **튀김 조리**가 함께 열린다. 해금 후 다음 장보기부터 새우가 상점에 나오고, 튀김을 고를 수 있다.

### 새우 (초안)
| 항목 | 값 |
|---|---|
| 가격 | 2,000원 |
| 유통기한 | 2일 |
| 기본 점수 | 80 |
| 속도 보정 | ×1.1 |
| 적합 방식 | 튀김 |

그림이 필요하다: `shrimp_shop.png`와 5단계 5장(`shrimp_raw`~`shrimp_burnt`). 규격은 [13 아트 가이드](13아트가이드.md).

### 튀김 조리 (초안)
| 항목 | 값 |
|---|---|
| 익는 속도 (중불, 초당) | 5 |
| 적정 구간 | 65~85 (폭 20) |
| 적합 재료 | 새우, 감자, 두부, 양파, 돼지고기 (달걀·김치는 궁합 0.6) |
| 고유 조작 | 기름 온도 유지: 불을 약불로 두면 눅눅해져 만족도 ×0.7 (조작 세부는 혁진님과 상의) |

- 배경 그림 `bg_cook_fry.png`이 필요하다. 도마·접시·버너 위치는 다른 조리 배경과 같게 한다.
- 해금 전에는 튀김 조리 선택지와 새우가 보이지 않는다.

### 도감 영향
- 방식이 4개가 되고 재료가 7개가 되어 가능한 조합이 늘어난다. 튀김 칸은 **해금 후에 나타나게** 하고, 기본 63칸 기준 칭호 조건은 그대로 둔다.
- 요리 이름은 `Recipes.NameOf`에 튀김 접미사("튀김")를 추가하고, 새우튀김 같은 자주 나오는 조합 몇 개를 이름표에 넣는다.
- 엄마의 레시피(`Recipes.Steps`)에 튀김 방식의 요령 한 줄을 추가한다.
