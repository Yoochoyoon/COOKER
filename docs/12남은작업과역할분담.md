## 개요
프로토타입 코드는 이미 7일 한 판이 돌아가는 상태다(타이틀 → 장보기 → 7일 → 결산, 마우스·키보드 모두 가능). 그래서 처음 [README](../README.md)의 역할(조리/루프를 처음부터 만들기)을 **다듬기·아트·AI·검증** 중심으로 다시 나눈다. 담당자 이름은 팀원이 정해 채운다.

## 현재 상태
| 항목 | 상태 |
|---|---|
| 7일 루프, 예산, 유통기한, 굶음 종료, 결산 | 됨 (스크립트로 한 판 완주 확인) |
| 굽기·볶기·끓이기, 불 조절, 방식별 조작 | 됨 (굽기·볶기·끓이기 모두 오너가 직접 플레이로 확인) |
| 재료별 투입·꺼내기 (트레이/팬/접시, 재료마다 익는 속도 다름) | 됨 (로직과 화면 확인. 속도 배율·방식별 시간 밸런스는 직접 플레이로 조정 필요) |
| 키보드 조작 | 됨 ([README](../README.md) 조작 키 표) |
| 주차 진행(다음 주 예산·재료값 상승), 1주차 난이도 완화, 주 1회 비상 라면 | 됨 (수치는 직접 플레이로 조정 필요: `Balance` 상수) |
| 도감, 엄마 힌트(고정 문구), 요리 이름(규칙) | 됨 |
| **마우스 클릭 실제 확인** | 안 됨 (도구로 입력이 닿지 않아 사람이 직접 확인 필요) |
| 스프라이트·UI 꾸미기 | 안 됨 (단색 사각형) |
| 생성형 AI | 안 됨 |
| 플레이테스트, 빌드, 발표 자료 | 안 됨 |

## 남은 작업 (우선순위)

### P0: 반드시
1. **직접 플레이로 검증**: 마우스로 시작 버튼부터 7일 완주, 볶기 젓기와 끓이기 뚜껑을 직접 해 본다. 막히는 곳을 버그 목록에 적는다.
2. **밸런스 조정** (`Data.cs`): 구간에 맞춰도 평균 만족도가 60 안팎이라 등급이 B에 머문다. 예산(10,000원), 등급 컷, 남은 재료 점수식을 직접 해 보며 조정한다.
3. **그래픽**: 재료 스프라이트(날것·적게 익힘·알맞음·많이 익힘·탄 것 5장 × 6종 = 30장), 팬·배경, 버튼 스킨. **프로젝트 오너가 직접 그린다.** 파일 이름과 규격은 [13 아트 가이드](13아트가이드.md)를 따르며, 넣기만 하면 게임에 나온다(재료 그림은 연결 완료, 팬·배경·버튼은 아직 단색). 어려우면 단색 도형 + 색 변화만 살려도 된다.
4. **Windows 빌드**: 시연용 exe가 열리는지 확인한다. 3일차 마지막 2시간에 하지 말고 2일차에 한 번 해 본다.
5. **플레이테스트**: [11 체크리스트](11플레이테스트체크리스트.md)로 지인 2~3명.

### P1: 시간이 되면
6. **생성형 AI 1개**: 식사 화면에서 요리 이름과 한 줄 레시피를 AI가 만든다. 호출 실패 시 지금의 규칙 이름으로 돌아가야 한다. API 키는 코드에 넣지 말고 로컬 설정 파일로 빼고 `.gitignore`에 넣는다.
7. **엄마 힌트 확장**: 지금은 재료별 1줄. 조건(유통기한 임박, 비싼 재료 등)에 따라 10개 안팎으로 늘린다.
8. **효과음·화면 연출**: 꺼내기, 탄 것, 성공 반응 정도.
9. **첫날 가이드 다듬기**: 조작 안내 문구를 테스트 결과에 맞춘다.
10. **발표 자료와 시연 시나리오**.

### P2: 프로토타입 이후
칭호(카테고리 조합) → 영구 버프, 튀기기·찌기, 모바일, 주차 진행, AI 완성 그림.

## 팀이 정해야 할 것
- [ ] 두 재료를 섞으면 만족도가 평균으로 떨어진다. 섞는 쪽에 보너스를 줄지
- [ ] 예산·등급 컷·다양성/남은 재료 점수식
- [ ] AI 사용 방식: 쓸 모델, API 키(개인 / 팀 공용), 발표 장소에 인터넷이 있는지
- [ ] 아트 방향: 그림을 직접 그릴지, AI 이미지·무료 에셋을 쓸지, 단색 도형으로 갈지
- [ ] 경진대회 날짜와 프로토타입 이후 범위

### 합칠 때 충돌을 줄이는 규칙
- 수치와 문구는 `Data.cs`에서만 고친다. 로직은 `Cook.cs`(조리)와 `GameFlow.cs`(흐름)로 나뉘어 있다.
- 같은 파일을 둘이 동시에 고치지 않는다. `GameFlow.cs`는 A와 B가 모두 만지므로 작업 전 `git pull`, 끝나면 바로 커밋·push한다.
- 새 기능은 가능하면 새 파일로 만들고 `GameFlow.cs`에는 호출 한 줄만 넣는다.
- 그림은 `Assets/Art/`에 넣고, 재료 이름과 상태가 파일명에 드러나게 한다. (예: `egg_raw.png`, `egg_cooked.png`, `egg_burnt.png`)

## 일정 (프로토타입 시작을 1일차로 본다)
**1일차 남은 시간**: A·B가 레포를 받아 Unity를 열고 한 판을 직접 플레이한다. 버그와 어색한 점을 목록으로 만든다. C는 스프라이트 작업을 시작한다.

**2일차**: A는 조작 튜닝과 스프라이트 적용, B는 AI 연동(먼저 이미지 모델 비교 시험, [docs/15](15AI요리그림비교시험계획.md))과 첫 빌드, C는 스프라이트·UI·힌트를 마무리한다. 저녁에 모두가 한 판씩 하고 밸런스를 조정한다.

**3일차 오전**: 수치 조정과 버그 수정. **오후**: 지인 플레이테스트. **마지막 2시간**: 최종 빌드, 발표 화면 확인. 새 기능은 넣지 않는다.

### 일정이 밀릴 때 버릴 순서
효과음 → 힌트 확장 → 스프라이트(단색 도형으로 대체). AI는 핵심 기능이라 마지막에 버린다. 7일 루프와 플레이테스트는 끝까지 지킨다.

## 확정된 사항 (2026-11-02)
- 두 재료를 모두 성공시키면 평균 만족도에 +10% 보너스 (구현 예정, 조리 담당)
- 점수는 "버틴 주차" 중심으로 변경, 주별 만족도·다양성은 참고용 (구현 예정, 루프 담당)
- 예산 10,000원과 재료값 상승률 8%는 현재 값 유지, 2일차 저녁 테스트 후 확정
- AI는 핵심 기능이라 일정을 앞당겨 먼저 한다(이름·설명은 Claude, 요리 그림은 이미지 모델). 실패하면 규칙 이름과 임시 접시로 대체. 모델은 [docs/15](15AI요리그림비교시험계획.md)의 비교 시험으로 정하고, API 키·발표장 인터넷은 그때 확인한다.
- 그림은 재료 30장 + 팬·트레이·접시, 배경·버튼은 단색 톤만 맞춘다.
- 김치·감자·삼겹살 가격 재확인은 B 파트, C 파트는 프로젝트 오너.

### 아직 정하지 않은 것
- 경진대회 날짜와 프로토타입 이후 범위
- 팀원 이름(A, B 담당자)
- 노션 페이지 위치와 공유 방법
