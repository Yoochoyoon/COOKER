## 개요
프로토타입 코드는 이미 7일 한 판이 돌아가는 상태다(타이틀 → 장보기 → 7일 → 결산, 마우스·키보드 모두 가능). 그래서 처음 [README](../README.md)의 역할(조리/루프를 처음부터 만들기)을 **다듬기·아트·AI·검증** 중심으로 다시 나눈다. 담당자 이름은 팀원이 정해 채운다.

## 남은 작업 (우선순위)

### P0: 반드시
1. **직접 플레이로 검증**: 마우스로 시작 버튼부터 7일 완주. 클릭·끌어다 놓기, 젓기 연타, 뚜껑 누르기, 밸브 돌리기를 직접 해 본다. 막히는 곳을 버그 목록에 적는다.
2. **밸런스 조정** (`Data.cs`): 조리 페널티가 겹치면 만족도가 낮아져 "생각보다 어렵다"는 의견이 있었다. 페널티 강도, 예산(10,000원), 등급 컷, 남은 재료 점수식을 직접 해 보며 조정한다.
3. **그래픽 마무리**: 식사·결산 화면 배경, 볶기·끓이기의 조작 칸(지금은 단색 카드), 버튼 스킨. 파일 이름과 규격은 [13 아트 가이드](13아트가이드.md)를 따른다.
4. **Windows 빌드**: 시연용 exe가 열리는지, **빌드에서 유료 AI 그림이 도는지** 확인한다. 빌드는 에디터와 달리 항상 유료 서비스를 쓴다([15](15AI요리그림비교시험계획.md)).
5. **플레이테스트**: [11 체크리스트](11플레이테스트체크리스트.md)로 지인 2~3명.

| Claude | 코드 수정 보조, 밸런스 계산, 문서 정리, 에디터 검증, 직접 플레이 검증이 필요한 부분의 사전 점검 | 전부 |

이전의 A(조리·감각)·B(루프·AI·빌드) 구분은 위 표로 대체됐다. 남은 조작 튜닝, 버그 수정, Windows 빌드, AI 연동 점검은 담당이 정해지지 않았으니 팀이 정한다.

### 합칠 때 충돌을 줄이는 규칙
- 수치와 문구는 `Data.cs`에서만 고친다. 로직은 `Cook.cs`(조리)와 `GameFlow.cs`(흐름)로 나뉘어 있다.
- 같은 파일을 둘이 동시에 고치지 않는다. `GameFlow.cs`는 A와 B가 모두 만지므로 작업 전 `git pull`, 끝나면 바로 커밋·push한다.
- 새 기능은 가능하면 새 파일로 만들고 `GameFlow.cs`에는 호출 한 줄만 넣는다.
- 그림은 `Assets/Resources/Art/`에 넣고, 파일 이름 규칙은 [13 아트 가이드](13아트가이드.md)를 따른다. (예: `egg_raw.png`, `egg_good.png`, `egg_burnt.png`)
- 원격 `main`에 합치기 전에 먼저 `git fetch`로 새 브랜치를 확인한다. `GameFlow.cs`를 둘이 따로 크게 고치면 충돌이 파일 전체에 나서 합치는 데 시간이 오래 걸린다(2026-11-04에 겪었다).

## 일정 (프로토타입 시작을 1일차로 본다)
**1일차 남은 시간**: A·B가 레포를 받아 Unity를 열고 한 판을 직접 플레이한다. 버그와 어색한 점을 목록으로 만든다. C는 스프라이트 작업을 시작한다.

**2일차**: A는 조작 튜닝과 스프라이트 적용, B는 AI 연동(먼저 이미지 모델 비교 시험, [docs/15](15AI요리그림비교시험계획.md))과 첫 빌드, C는 스프라이트·UI·힌트를 마무리한다. 저녁에 모두가 한 판씩 하고 밸런스를 조정한다.

**3일차 오전**: 수치 조정과 버그 수정. **오후**: 지인 플레이테스트. **마지막 2시간**: 최종 빌드, 발표 화면 확인. 새 기능은 넣지 않는다.

### 일정이 밀릴 때 버릴 순서
효과음 → 힌트 확장 → 스프라이트(단색 도형으로 대체). AI는 핵심 기능이라 마지막에 버린다. 7일 루프와 플레이테스트는 끝까지 지킨다.

## 확정된 사항 (2026-11-02)
- 두 재료를 모두 성공시키면 평균 만족도에 +10% 보너스 (구현 예정, 조리 담당)
- 점수는 "버틴 주차" 중심으로 변경, 주별 만족도·다양성은 참고용 (구현 예정, 루프 담당)
- 예산 10,000원과 재료값 상승률 8%는 현재 값 유지, 2일차 저녁 테스트 후 확정
- AI는 핵심 기능이라 일정을 앞당겨 먼저 한다(이름·설명은 Claude, 요리 그림은 이미지 모델). 실패하면 규칙 이름과 임시 접시로 대체. 모델은 [docs/15](15AI요리그림비교시험계획.md)의 비교 시험으로 정하고, API 키·발표장 인터넷은 그때 확인한다.
- 그림은 재료 30장 + 팬·트레이·접시, 배경·버튼은 단색 톤만 맞춘다.
- 김치·감자·삼겹살 가격 재확인은 B 파트, C 파트는 프로젝트 오너.

## 확정된 사항 (2026-11-04)
- **통합**: 팀원의 `feature/cooking-ui-ai-photo`(UI 틀, AI 요리 사진, 하루 선택 끌어다 놓기, 엄마의 전언)와 `dex`(도감)를 `main`에 합쳤다. 상점·조리 아트, 조리 페널티, 익힘 게이지, 섞어먹기 보너스는 기존 `main` 쪽 것을 그대로 옮겼다.
- **조작은 기존 방식 유지**: Space 탭·연타·누르기와 클릭·끌어다 놓기. 팀원 쪽의 "도구를 손에 드는" 방식(`ToolHold`)은 쓰지 않는다. 대신 가스 밸브 손잡이로 불을 조절하는 것은 팀원 쪽 것을 쓴다.
- **망친 요리는 AI 그림을 만들지 않는다.** 도감에 들어가는(성공한) 요리만 만든다.
- **AI 그림은 유료 BAZE 모델(`gpt-image-2.5-sunburst`)**, 단 **에디터에서 테스트하는 동안은 무료 서비스만** 쓴다. 빌드는 유료.
- 요리 이름은 AI가 실제 음식 이름으로 지어 준다 (먼저 아는 요리 이름을 보여 주고, 도착하면 바꾼다).
