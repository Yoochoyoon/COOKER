# 28 재료 넣는 순서 명세

모든 조리 방식에서 재료를 정해진 순서대로 넣게 하는 기능의 구현 명세다. 담당은 [윤혁진](#9-담당)이고, 화면 배치는 유초윤 님이 맡는다.

> **미확정** 표시 항목은 팀에서 확정한 뒤 이 문서를 고친다.

## 1. 목적

- 재료를 아무 순서로 넣지 않고, 방식마다 맞는 순서로 넣게 한다.
- 순서가 틀리면 맛을 깎되, 실패로 바로 끝내지는 않는다.
- 처음 몇 판은 힌트를 보여 주고, 익숙해지면 힌트를 줄인다.

## 2. 순서 규칙

재료는 "오래 익는 재료 → 보통 재료 → 빨리 익는 재료" 세 단계로 나눈다. 방식마다 재료 목록을 따로 둔다.

| 방식 | 순서 (앞 → 뒤) |
| --- | --- |
| 굽기 | 감자 → 돼지고기 → 양파 → 김치 → 달걀 |
| 볶기 | 감자, 양파 → 돼지고기 → 김치 → 달걀 |
| 끓이기 | 감자 → 돼지고기 → 두부 → 달걀 |

- 같은 단계 안의 재료(예: 볶기의 감자와 양파)는 어떤 순서로 넣어도 맞다.
- 단계를 건너뛰어 넣거나, 뒤 단계 재료를 먼저 넣으면 위반이다.
- 한 번 넣은 재료는 다시 넣지 않는다. 재료별로 한 번씩만 넣는다.

**미확정:** 위 목록이 맞는지, 특히 볶기의 김치 위치는 확인이 필요하다.

## 3. 위반 처리

| 항목 | 내용 |
| --- | --- |
| 위반 판정 | 넣는 순간 정해진 순서와 다르면 위반으로 기록한다. |
| 맛 보정 | 위반 1회마다 전체 익힘 값에 보정 계수를 곱한다. 계수는 `BalanceData`에 둔다. |
| 누적 | 위반이 여러 번이면 보정을 곱해서 누적한다. |
| 실패 여부 | 위반만으로 실패(굶음)가 되지는 않는다. |

**미확정:** 보정 계수 값. 제안값은 1회당 0.9다.

보정은 전체 익힘 명세(`docs/27`)의 계산 결과에 적용한다.

## 4. 힌트

| 항목 | 내용 |
| --- | --- |
| 힌트 시기 | 처음 3판에서는 힌트를 띄운다. 3판이 지나면 힌트를 숨긴다. |
| 힌트 내용 | 말풍선(`cook_tip`)에 다음에 넣을 재료를 한 줄로 알려 준다. 예: "다음은 돼지고기예요." |
| 틀렸을 때 | 틀린 순서를 넣으면 말풍선에 올바른 다음 재료를 알려 준다. 실패로 처리하지 않는다. |
| 힌트 횟수 저장 | 판 수는 기존 세이브와 분리해 저장한다. 저장 키 이름은 새로 정한다. |

**미확정:** 힌트를 3판으로 할지, 다른 기준으로 할지. 힌트 횟수를 저장할지, 세션마다 초기화할지.

## 5. 화면 연결 (데이터만)

화면 배치와 표시 방식은 유초윤 님이 정한다. 이 명세는 화면에 넘길 데이터만 정한다.

- **현재 기대 재료:** 지금 넣을 차례인 재료 이름.
- **넣은 목록:** 지금까지 넣은 재료를 넣은 순서대로.
- **위반 횟수:** 이번 판의 위반 횟수.
- **힌트 표시 여부:** 힌트를 보여 줄지 말지.

## 6. 코드 연결 (제안)

새 파일 `Cook.Order.cs`에 partial class로 둔다. 기존 파일에는 호출만 추가한다.

- **속성:** 방식별 순서 목록, 현재 기대 재료, 넣은 목록, 위반 횟수, 힌트 표시 여부.
- **메서드:** 재료를 넣을 때 순서 확인, 위반 기록, 보정 계수 반환, 판 시작 시 초기화.

`Cook.cs`의 재료 넣기 처리에서 순서 확인을 한 번 호출한다. 말풍선 표시는 `GameFlow.Cook.cs`에서 맡는다. 이 파일은 영은 님 담당이므로 요청으로 진행한다.

## 7. 도움말

- `Help.cs`(윤혁진 님 담당)의 조작 설명에 재료 순서 규칙을 한 단락으로 추가한다.
- 문구는 세 방식의 순서 표를 그대로 옮기지 않고, "오래 익는 재료부터 넣어요"처럼 짧게 쓴다.

## 8. 수치 목록 (`BalanceData`)

- 방식별 순서 목록 (단계 구분 포함)
- 위반 1회당 보정 계수 (제안 0.9)
- 힌트 표시 판 수 (제안 3)

수치를 정하면 바꾼 값과 이유를 `docs/09`에 한 줄씩 남긴다.

## 9. 담당

- **윤혁진:** `Cook.Order.cs`(새 파일), 순서 판정, 위반 기록, 보정 계산, 힌트 데이터, `Help.cs` 문구.
- **유초윤:** `Cook.cs` 호출 승인, `BalanceData` 수치, 화면 배치와 표시, `docs/09` 기록.
- **영은:** `GameFlow.Cook.cs`의 말풍선 표시 연결. 요청으로 진행한다.

## 10. 테스트

- 방식마다 올바른 순서로 넣었을 때 위반이 0인지 확인한다.
- 단계를 건너뛰었을 때 위반이 기록되는지 확인한다.
- 같은 단계 안의 재료는 순서를 바꿔도 위반이 아닌지 확인한다.
- 위반이 여러 번일 때 보정이 누적되는지 확인한다.
- 위반만으로 실패(굶음)가 되지 않는지 확인한다.
- 처음 3판에서 힌트가 뜨고, 그 뒤에는 뜨지 않는지 확인한다.
- 재료를 두 번 넣지 못하는지 확인한다.
- 네 방식 모두에서 순서 목록이 맞는지 확인한다.
- 빌드 전에 인터넷을 끊고 한 판을 끝까지 돌린다.

## 11. 확정이 필요한 것

1. **순서 목록:** 굽기, 볶기, 끓이기 목록이 맞는지. 특히 볶기의 김치 위치.
2. **보정 계수:** 위반 1회당 0.9가 맞는지.
3. **힌트 기준:** 3판으로 할지, 힌트 횟수를 저장할지.
