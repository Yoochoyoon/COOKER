# 32. AI로 만든 요리 이름과 레시피 기록

**무엇**: 도감과 엄마 추천에 쓰는 요리 이름 120개와, 도감 상세의 레시피 글 120개.
**어떻게**: 개발 중에 Google Gemini 텍스트 모델(`gemini-2.5-flash`)을 한 번 불러 만들었고, 결과를 `Assets/Resources/Data/DishText.json`에 저장했다.
**실행 중에는 AI를 쓰지 않는다.** 게임은 이 파일만 읽는다 (인터넷·API 키 불필요). 파일이 없거나 항목이 없으면 예전 방식(기본 이름 + 문장 조립 레시피)으로 대신한다.

## 범위
- 도감 칸 112개(재료 1~2개 × 방식 4개: 굽기, 볶기, 끓이기, 튀기기) + 재료 3개로 이미 이름이 있던 요리 8개 = 120개.
- 이름은 `Recipe.cs`의 `names`에 이미 정해 둔 37개를 그대로 두고, 나머지는 AI가 지었다. 칭호의 "대표 레시피 수집"(`Recipes.IsNamed`)은 예전 37개만 센다 (바뀌지 않는다).
- 레시피는 한 요리에 4~6줄, 한 줄 60자 이내, 쓸 수 있는 재료는 게임의 재료 7종과 기본 양념(식용유, 소금, 후추, 간장, 참기름, 설탕, 전분가루, 튀김가루, 물)뿐이다.

## 사람이 고친 것 (솔직한 기록)
- AI가 같은 이름을 여러 요리에 붙인 6곳을 직접 바꿨다: 김치/굽기 → 김치부침, 김치/볶기 → 묵은지볶음, 김치+돼지고기/볶기 → 돼지김치볶음, 김치/끓이기 → 김칫국, 김치+돼지고기/끓이기 → 돼지김치찌개, 감자+김치/튀기기 → 김치감자튀김(오타 수정).
- 재료 두 개를 단순히 이어 붙인 이름(예: 두부양파볶음)이 남아 있다. 실제로 그런 요리 이름이 없는 조합이라 그대로 두었다.
- 레시피 내용(불 세기·시간)은 한 번 훑어 확인했지만, 요리 전문가가 검수한 것은 아니다.

## 다시 만들려면
`UserSettings/CookerApiKeys.txt`의 `GEMINI_API_KEY`가 필요하다 (이 파일은 깃에 올리지 않는다). 키는 코드·문서·로그 어디에도 적지 않는다.
